## 0. Принципы плана

1. **Каждый этап маленький и независимый.** Один этап = один коммит/PR, который
   можно откатить (`git revert`) без последствий для остальных этапов.
2. **Каждый этап поведенчески нейтрален** — на выходе бот отвечает пользователю
   ровно то же самое, что и на входе в этап. Если для устранения проблемы из
   `AUDIT.md` требуется *изменить* поведение (например, унифицировать семантику
   аналитики между `bot.py` и пакетом) — такой шаг **вынесен за пределы плана**
   в раздел «Фаза I» как отдельное продуктовое решение, а не как «безопасный
   рефакторинг».
3. **Порядок фаз — от наименее рискованных к наиболее рискованным.** Внутри
   каждой фазы этапы тоже упорядочены по риску.
4. **У каждого этапа есть проверка (verification).** Поскольку в проекте нет
   тестов (`AUDIT.md §5.6`), Этап 0 вводит минимальный тестовый каркас именно
   для того, чтобы последующие этапы можно было проверять объективно, а не
   «на глаз».
5. **Обнаруженные «ловушки»** (одинаковые имена констант с разным смыслом,
   скрытые рантайм-связи) явно помечены знаком **⚠ ЛОВУШКА** — эти места нельзя
   трогать «по аналогии», не проверив вручную каждое значение.

### Формат карточки этапа

```
Этап X.Y — <название>
Файлы:        <что затронуто>
Зависит от:   <номера предыдущих этапов, либо "нет">
Риск:         низкий / средний / высокий
Почему безопасно:  <обоснование отсутствия изменений в поведении>
Действия:     <что физически сделать>
Проверка:     <как убедиться, что поведение не изменилось>
Откат:        <как отменить, если что-то пошло не так>
```

## Фаза D — Единый источник констант ролей/порогов

⚠ **Общая ловушка для всей фазы:** в проекте есть переменные с **одинаковым
именем `RANK_THRESHOLDS`, но с разным смыслом**:
- `bot/config/constants.py` и `bot/services/role_service.py`:
  `RANK_THRESHOLDS: dict[str, int]` — пороги **оборота в рублях** для выдачи
  ранговой Discord-роли (`{"Standard": 0, "Premium": 5000, ...}`).
- `bot/services/referral_service.py`: `RANK_THRESHOLDS: list[int]` — пороги
  **XP** для прогресс-бара в `/profile` (`[50, 250, 1000, 5000, 10000]`).

Это два совершенно разных бизнес-правила, случайно названных одинаково. **Ни
один из нижеследующих этапов не должен их объединять** — только устранять
дублирование внутри *одного и того же* смыслового набора.
