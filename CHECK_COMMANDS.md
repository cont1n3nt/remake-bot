# Чек-лист команд бота

Полный список слэш-команд и кнопочных потоков на момент коммита. Отмечайте
`[x]` по ходу проверки. Для каждой команды — что нажать и что проверить
(в интерфейсе и/или в БД).

Общие проверочные запросы к БД (подставить реальный путь, обычно
`~/stalbot/data/cache.sqlite3`):

```bash
sqlite3 ~/stalbot/data/cache.sqlite3 "SELECT * FROM deals ORDER BY id DESC LIMIT 5;"
sqlite3 ~/stalbot/data/cache.sqlite3 "SELECT * FROM players WHERE nick_norm = '<ник>';"
sqlite3 ~/stalbot/data/cache.sqlite3 "SELECT * FROM catalog_items WHERE name_norm LIKE '%<название>%';"
sqlite3 ~/stalbot/data/cache.sqlite3 "SELECT * FROM item_price_history ORDER BY id DESC LIMIT 5;"
```

## 1. Профиль и прогрессия (`profile.py`)

- [ ] **`/profile <ник>`** — свой профиль и чужой (если `ADMIN_CAN_VIEW_ANY_PROFILE=true`).
  Coins/XP/ранг/реферальная роль должны совпадать с тем, что ожидается по
  сделкам игрока. Проверить игрока без сделок — не должно падать.
- [ ] **`/referrals <ник>`** — список рефералов известного реферера.

## 2. Сделки (`transactions.py`)

- [ ] **`/add`** — зафиксировать сделку (покупка/продажа, ник, сумма,
  discord-аккаунт, опционально реферал). После:
  ```sql
  SELECT * FROM deals ORDER BY id DESC LIMIT 1;
  ```
  `source='bot'`, Coins/XP посчитаны сразу. `/profile` этого ника обновился.
- [ ] `/add` на **новом** нике — должен создать нового `players`, а не упасть.
- [ ] `/add` с реферал_ник **без** реферал_discord — должно показать
  предупреждение «привязка не выполнена», сделка при этом всё равно пишется.
- [ ] `/add` на ник, уже привязанный к другому Discord-аккаунту — должно
  показать подтверждение перепривязки (`ConfirmView`), и не перепривязывать
  без подтверждения.
- [ ] **`/del_deal <ID>`** *(новая команда)* — взять ID из `/logs` (см. п.7)
  или из `SELECT id FROM deals ORDER BY id DESC LIMIT 1;`.
  - Должно показать подтверждение с деталями сделки (ник, тип, сумма,
    Coins/XP, дата) перед удалением.
  - Отмена (кнопка «Отмена» в `ConfirmView`) — сделка должна остаться в БД.
  - Подтверждение — сделка удаляется:
    ```sql
    SELECT * FROM deals WHERE id = <ID>;   -- должно вернуть пусто
    ```
    `/profile` игрока должен обновиться **сразу** (прогресс пересчитывается
    синхронно внутри команды, не нужно ждать 5 минут фонового пересчёта).
  - Несуществующий ID — должно вернуть «Сделка с таким ID не найдена», не падать.

## 3. Тикеты — кнопочный поток, не слэш-команды (`tickets/cog.py`)

Открывается автоматически при создании канала-тикета (интеграция с Ticket Tool).

- [ ] **Продажа предметов** — кнопка формы → `TicketFormModal` → выбор способа
  доставки (`DeliveryMethodView`) → прикрепить скриншот → подтвердить.
  Карточка тикета должна сразу показать реальные Coins/XP.
- [ ] **Продажа бустов** — то же самое, для типа "бусты".
- [ ] **Заказ бустов** — форма → `BoostMultiSelectView`/`OrderEditorView`
  (выбор нескольких бустов и количеств) → `OrderSummaryView` → подтвердить.
- [ ] **✏️ Редактировать** на карточке скупки (заявка 13.09.2026 п.9) —
  открывает ту же форму, заполненную текущими значениями; после submit
  показывает «было → стало» и просит подтверждения, и только потом пишет.
  Проверить: доступна автору и админу, недоступна постороннему и после
  подтверждения заявки; правка админом **не** переписывает автора тикета.
- [ ] После подтверждения любого тикета — ответ админу теперь полная
  карточка сделки как у `/add` (заявка 13.09.2026 п.4): тип, ник, Discord,
  сумма, Coins/XP, реферал, дата.
- [ ] После завершения **заказа бустов** в лог-канал уходит
  «💼 Экономика заказа» (заявка 13.09.2026 п.7): выручка, себестоимость,
  чистая прибыль, маржа. Если есть позиции без связи с убежкой — эмбед
  обязан сказать, сколько их не учтено, и предупредить, что настоящая
  прибыль ниже показанной. Проверить на заказе из связанных и несвязанных
  позиций сразу.
- [ ] Прикрепить файл неверного формата/размера (не `png/jpeg/webp`, либо
  больше 8 МБ) — должно вежливо отказать, не падать.
- [ ] После подтверждения любого тикета проверить, что `players.discord_id`
  проставился:
  ```sql
  SELECT discord_id FROM players WHERE nick_norm = '<ник>';
  ```

## 4. Калькулятор скупки (`purchase_calculator.py`)

- [ ] **`/skupka`** — постит карточку с кнопками «📋 Вставить список» /
  «🔄 Сбросить».
- [ ] Массовый ввод `Название xКоличество` — проверить разделители `x`/`х`/`×`.
- [ ] Вставить заведомо кривые строки вперемешку с нормальными — кривые
  должны попасть в `not_parsed`/`not_found`/`ambiguous`, а не уронить весь ввод.
- [ ] `Название x0` — должно удалить позицию из списка, а не выдать ошибку.
- [ ] Вставить 100+ позиций одним разом — не должно упираться в лимит строк.
- [ ] «🔄 Сбросить» — обнуляет весь список одной кнопкой.

## 5. Каталог и цены (`catalog.py`, `pricing.py`)

- [ ] **`/item_add`** — добавить новый предмет (название, категория,
  цена). Проверить, что появился в `/price_list`.
- [ ] **`/del_item <предмет>`** — это **soft-delete**, не физическое удаление:
  ```sql
  SELECT deleted_at FROM catalog_items WHERE name = '<название>';
  ```
  должно быть не `NULL`.
- [ ] **`/price_list`** — полный список ресурсов и бустов.
- [ ] **`/give_price`** — выгрузка текущего прайса в `.txt`.
- [ ] **`/setprice <ресурс> <цена>`** — применить к `resource`. Попробовать
  применить к `boost` — должна вернуться ошибка `InvalidCategoryPriceError`
  («У ресурса указывается только цена покупки...»), а не тихо сработать.
- [ ] **`/setboost <буст> <цена>`** — аналогично, только для `boost`.
- [ ] **`/new_price <файл.txt>`** — взять файл из `/give_price`, поменять
  пару цифр, залить обратно. Если `PRICE_IMPORT_CONFIRM=true` — должно
  показать превью изменений с подтверждением, не применяться сразу.
- [ ] После любого изменения цены проверить лог:
  ```sql
  SELECT * FROM item_price_history ORDER BY id DESC LIMIT 5;
  ```

## 5а. База игроков (`database.py`)

- [ ] **`/database`** — постраничный список; поиск по нику/Discord.
- [ ] Под списком кнопки **🏅 По рангам** и **🤝 По реф-ролям** (заявка
  13.09.2026 п.5). Нажатие даёт кнопки всех пяти тиров с числом носителей,
  выбор тира — список «ник → @Discord».
- [ ] Носители читаются из `player_progression`, а не из ролей Discord —
  то есть показывают, кому ранг **положен по расчёту**. Расхождение с
  живыми ролями здесь и должно быть видно; чинится через `/resync_roles`.
- [ ] В карточке игрока реферер показан ником, а не «ID 12».

## 6. Рефералы и ранги вручную (`manual.py`)

- [ ] **`/set_referral <игрок> <реферер>`** — должно работать **без
  существующей сделки** у игрока (осознанное изменение поведения на Э7) —
  проверить на паре новых ников без единой сделки.
- [ ] **`/set_rank <игрок> <ранг>`** — выдаёт Discord-роль вручную. Убедиться,
  что дальнейший фоновый пересчёт прогрессии не сбрасывает эту роль
  (`manual_rank_role` в `progression_state` должен быть выставлен).
- [ ] **`/link_discord <ник> <аккаунт>`** — привязка; при смене уже
  привязанного аккаунта спрашивает подтверждение.
- [ ] **`/unlink_discord <ник>`** (заявка 13.09.2026 п.11) — отвязка после
  подтверждения. **Главное, что надо проверить:** с отвязанного аккаунта
  действительно сняты ранговая и реферальная роли — после отвязки фоновый
  пересчёт их уже не снимет никогда. Прогресс ника (Coins, XP, сделки)
  остаётся нетронутым.

## 6а. Синхронизация ролей (`roles.py`)

- [ ] **`/resync_roles`** — пересчёт и исправление ролей всех игроков
  сейчас, с отчётом по каждому изменению.
- `/role_audit` удалён (заявка 13.09.2026 п.11), его больше нет.

## 7. Статистика и архив (`stats.py`)

- [ ] **`/logs`** — архив сделок с пагинацией (по 25 на страницу). Каждая
  строка теперь показывает `(ID: N)` рядом с номером дня — именно этот ID
  используется в `/del_deal`.
- [ ] **`/day <ДД.ММ.ГГГГ>`** — статистика за конкретный день, включая день
  с интерполированными сделками (помечены `≈` — `occurred_at_kind =
  'sheet_interpolated'`).
- [ ] **`/week <начало> <конец>`** — за произвольный период.
- [ ] **`/month <месяц> <год>`** — месяц выбирается из выпадающего списка.

## 8. Плакаты (`posters.py`)

- [ ] **`/poster тип=Бусты`**
- [ ] **`/poster тип=Заказ бустов`** (`boost_purchases`)
- [ ] **`/poster тип=Ресурсы`**
  Проверить, что вёрстка не съезжает на реальных длинных именах предметов
  из живого каталога (не только на тестовых данных).

### Раскладка в базе (заявка 13.09.2026 п.6)

**Сначала** разовый импорт — см. README, раздел «Первый запуск». До него
плакаты будут пустыми.

- [ ] **`/poster_item list <плакат>`** — что сейчас на плакате. Позиции с
  проблемами помечены: «нет в каталоге», «нет картинки», «нет цены». Внизу —
  список того, что есть в каталоге с ценой, но на плакат не попало.
- [ ] **`/poster_item add`** — предмет + **вложение-скриншот** + секция.
  Автокомплит предмета показывает только свою сторону сделки (на плакате
  бустов — бусты). Повторное добавление того же предмета должно отказать.
  Предмет не той категории — отказать.
- [ ] **`/poster_item icon`** — заменить картинку. Проверить, что старый файл
  из `POSTER_ICONS_DIR` исчез, а новый появился.
- [ ] **`/poster_item move`** — секция и/или позиция (нумерация с 1).
- [ ] **`/poster_item remove`** — убирает с плаката, **из каталога не удаляет**.
- [ ] После каждой правки — `/poster` должен показать изменение.
- [ ] **`/item_add` с аргументами `плакат` + `скриншот`** — предмет сразу
  встаёт на плакат. Указать один аргумент без второго — ошибка, и предмет
  **не** должен создаться.
- [ ] **`/del_item`** — снимает предмет со всех плакатов, в ответе пишет
  сколько позиций снято.

## 9. Служебное

- [ ] **`/tag <пользователь>`** — уведомление в тикете, упоминание реально
  приходит адресату.
- [ ] **`/healthcheck`** — отчёт о состоянии: схема БД, `integrity_check`,

## 10. Себестоимость убежки (`shelter_cost.py`, заявка 21.08.2026)

- [ ] **`/cost <предмет>`** — себестоимость конкретного предмета убежки
  (автокомплит по всем `shelter_items`), с источником (`своя цена` /
  `рыночная цена` / `крафт` / `не определена`).
- [ ] **`/cost`** без аргумента — постраничный список себестоимости по
  всему ассортименту.
- [ ] **`/cost категория=Предметы|Бусты`** (заявка 13.09.2026 п.10) — тот же
  список, но только по одной стороне каталога. Фильтр идёт через
  `catalog_items.shelter_item_id`, поэтому непривязанные к убежке позиции
  в список не попадут — это ожидаемо и написано в самом эмбеде.
- [ ] **`/precost <предмет> <новая_цена>`** — предпросмотр: список
  предметов, чья себестоимость изменилась бы при гипотетической цене, было
  → стало. Ничего не пишет в БД — проверить, что цена предмета в базе не
  изменилась после вызова.
- [ ] **`/precost` с несколькими парами** (заявка 13.09.2026 п.12) — до
  четырёх `предмет/новая_цена`. Шапка ответа перечисляет все подмены.
  Указанный предмет без цены (или наоборот) — ошибка с номером позиции,
  а не тихое игнорирование.
