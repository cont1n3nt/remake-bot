## ADR-001 — Единственный источник истины: пакет `bot/`

Дата: 2026-07-30
Статус: **принято**
Соответствует: `REFACTORING_PLAN.md`, Этап B.1

### Контекст

В репозитории одновременно существуют две полные независимые реализации
одного и того же Discord-бота — см. `AUDIT.md §2.2, §5.1`:

- **`bot/`** — слоистый пакет (Cog → Service → Repository), 7 когов, чистый
  импорт-граф без циклов.
- **`bot.py`** — монолитный файл в корне (1743 строки), дублирующий тот же
  функционал одним файлом.

Оба технически исполняемы. Нужно формально зафиксировать, какой из них
считается продакшеном, чтобы дальнейший рефакторинг (Фазы C–G) применялся
только к нему, а `bot.py` не продолжал расходиться параллельно.

### Решение

**`bot/` — единственная эксплуатируемая реализация проекта.**

Основания:
1. `selfbot/scripts/start_bot.sh` — фактический прод-скрипт запуска —
   выполняет `venv/bin/python -m bot`, то есть запускает пакет `bot/`, а не
   `bot.py`.
2. `bot.py` отсутствует в `discord_trade_bot.egg-info/SOURCES.txt` — не
   является частью устанавливаемого пакета.
3. Обычный `import bot` резолвится в пакет `bot/` (`bot/__init__.py`), а не
   в файл `bot.py` — монолит недостижим даже случайным импортом под именем
   `bot` (подтверждено в `BASELINE.md §2.1`).
4. По каждому найденному поведенческому расхождению (см. ADR-002 ниже)
   версия в `bot/` либо новее, либо содержит устранённый баг, которого нет
   в `bot.py`.

### Последствия

- Любые новые правки функциональности — только в `bot/`.
- `bot.py` замораживается (см. ADR-002 / Этап B.3) и впоследствии будет
  удалён в Фазе H `REFACTORING_PLAN.md`.

## ADR-002 — Реестр поведенческих расхождений `bot.py` ↔ `bot/`

Дата: 2026-07-30
Статус: **зафиксировано**
Соответствует: `REFACTORING_PLAN.md`, Этап B.2
Источник расхождений: `AUDIT.md §5.1`

| # | Расхождение | `bot.py` | `bot/` | Что новее/надёжнее | Переносить в `bot/`? |
|---|---|---|---|---|---|
| 1 | Семантика аналитики (`is_buy`/`is_sell` → `total_buy`/`total_sell`) | Считает суммы напрямую от `tx["type"]`, без пояснения бизнес-смысла | В `bot/cogs/analytics.py::_build_analytics_embed` есть развёрнутый комментарий, разъясняющий семантику «продал боту / купил у бота», агрегация иначе адаптирована к этой семантике | `bot/` — осмысленная, документированная реализация | **Нет.** `bot.py` не содержит ничего, отсутствующего в `bot/`; расхождение — это упрощённая/менее точная версия в `bot.py`, а не более полная |
| 2 | Параметры `/week` | `год` + `неделя` (номер ISO-недели) | `диапазон` строкой `ДД.ММ.ГГГГ - ДД.ММ.ГГГГ` | Не «баг vs фикс» — два разных UX для одной команды | **Нет.** Смена UX — продуктовое решение, а не безопасный перенос; вынесено в `REFACTORING_PLAN.md` Фазу I. Т.к. `bot/` — источник истины (ADR-001), действующим считается вариант `bot/` |
| 3 | Запись цен в Google Sheets (`sync_prices_to_sheets`) | Поячеечная запись `update_cell` в цикле (`_sync_prices_to_sheets`) | Батч `update_cells`, с комментарием в коде, объясняющим, что поячеечная запись раньше проглатывала ошибки квоты Google Sheets API | `bot/` — содержит уже исправленный баг | **Нет.** `bot.py` содержит устаревшую, уже отревертенную ошибку — переносить нечего, наоборот, это причина не использовать `bot.py` |
| 4 | Риск случайного запуска `python bot.py` вместо `python -m bot` | Даёт полностью отдельный процесс со своим `main()`/`on_ready`/`setup_hook` и всеми расхождениями выше | Официальная точка входа (`start_bot.sh`) | — | Не применимо к переносу кода; риск устраняется удалением `bot.py` целиком в Фазе H |

### Вывод

По состоянию на 2026-07-30 **ни один пункт `bot.py` не содержит
функциональности, которую стоило бы перенести в `bot/` перед удалением**.
Все расхождения — это либо уже исправленные в `bot/` баги, либо
устоявшийся в проде UX `bot/`, который и остаётся действующим согласно
ADR-001. Условие для перехода к Фазе H (`REFACTORING_PLAN.md`) выполнено
на уровне анализа; сама Фаза H требует отдельного явного подтверждения
пользователя перед удалением файла.

### Финальная сверка перед Фазой H (Этап H.1)

Дата: 2026-07-30. Повторно проверено перед удалением:
- `git log --oneline -- bot.py` со дня заморозки (коммит `fbd475c`)
  содержит только сам коммит заморозки — файл не редактировался ни разу,
  таблица расхождений выше не устарела.
- `README.md` не содержит упоминаний `bot.py` или `python -m bot` — только
  `pip install -e .` и команду `bot`; обновлять нечего.
- Пользователь ознакомлен с таблицей расхождений (ADR-002) и явно
  подтвердил переход к Фазе H в диалоге 2026-07-30 — это и есть «ревью
  вторым человеком/владельцем продукта», которого требовал Этап H.1.

Условие для удаления выполнено полностью.

## Заморозка `bot.py` (Этап B.3)

С 2026-07-30 `bot.py` не редактируется. Единственная правка, внесённая
после этой даты, — маркер заморозки в шапке самого файла (комментарий,
без изменения исполняемого кода), сделанный в этом же коммите. Любое
код-ревью после этой даты должно отклонять PR, меняющие `bot.py` (кроме
удаления файла целиком в Фазе H).
